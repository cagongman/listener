# 모니카·전문 봇·n8n 확장 계획

작성일: 2026-11-19. 현재 요청의 구현 범위는 listener의 대화 연결 개선이다. 봇 생성, 시세 API 연결, n8n 설치·워크플로우 배포는 이 문서에 정리한 후속 단계다.

## 1. 먼저 완성할 입력 기반

이번 listener 변경은 다음 연결을 제공한다.

```text
마이크 → 공유 Whisper → 호출어/제어 명령 판별
  → SessionController → 인증된 Hermes Gateway
    ├─ 선택된 세션에 후속 입력 (작업 중에는 FIFO 접수)
    ├─ 새 대화 생성 / 이전 대화 선택 / 목록 선택
    └─ 같은 세션 ID의 CLI 화면 다시 열기
```

CLI 창과 에이전트 세션은 별도로 관리한다. 창이 열려 있어도 음성 감지를 유지한다. 현재 선택과 직전 대화는 프로필·작업 폴더별로 저장한다. 이미 접수한 요청은 새 대화로 전환해도 원래 세션에 남는다. 전송 결과가 불명확하면 자동 재전송하지 않는다.

## 2. 목표 구조와 역할

```text
사용자 음성
   │
listener-hermes ── SessionRouter / 상태 알림
   │
Hermes Gateway
   └─ monica 프로필의 고정 Bot Chat: 요청 분배·종합·사용자 응대
        ├─ keyword 봇: 뉴스/검색의 키워드 변화, 근거와 발생 시각 분석
        └─ stocks 봇: 종목 식별, 시세/거래량/뉴스를 함께 분석
              │
        공통 데이터 도구 (API 또는 MCP)
              ├─ 현재가 / 과거 시세 / 뉴스 / 키워드 집계
              └─ 같은 응답 스키마, 캐시, 출처와 데이터 기준 시각

n8n
  일정·수집·저장·조건 검사·중복 방지·알림
   ├─ 공통 데이터 API 호출
   └─ 중요 이벤트만 분석 요청 → 모니카 → 전문 봇 → 결과 알림
```

| 구성 | 담당 | 유지할 상태 |
|---|---|---|
| listener | 음성 입력, 대화 선택과 전송, 접수 상태 표시 | 현재/이전 세션 ID, 입력 ID와 접수 결과 |
| 모니카 | 의도 파악, 적절한 봇 선택, 결과 종합 | 사용자 선호, 진행 작업과 결과 참조 |
| 키워드 봇 | 키워드 변화 및 관련 뉴스의 분석 | 관심 주제, 비교 기준과 과거 요약 |
| 주식 봇 | 시세·거래량·뉴스의 분석 | 관심 종목, 분석 기준과 과거 요약 |
| API/MCP 도구 | 검증 가능한 데이터 반환 | API 인증, 캐시, 요청 제한과 오류 상태 |
| n8n | 반복 실행과 외부 서비스 연계 | 워크플로우 실행 기록, 조건/알림 중복 방지 |

## 3. 스킬·도구·워크플로우의 구분

- **스킬**에는 조회 순서, 비교 기간, 근거 확인, 데이터가 없을 때의 응답 방식, 보고서 형식을 적는다.
- **도구**는 실제 현재가·거래량·뉴스를 조회하고 구조화된 값을 반환한다.
- **n8n**은 정해진 일정이나 이벤트에 따라 도구를 호출하고, 조건을 만족하면 봇의 분석과 결과 전달을 이어 준다.

초기에는 주식 봇이 요청을 받을 때 API 도구를 직접 호출한다. 일정 수집·알림 요구가 생기는 단계에서 n8n을 연결한다. 초당 많은 시세 틱의 상시 수집은 전용 스트리밍 수집기가 담당하고 n8n은 후속 처리와 알림을 맡는다.

## 4. 단계 A — 모니카 고정 대화와 전문 봇

1. `monica`, `keyword`, `stocks` 프로필의 역할·설명·모델·기억 범위를 정한다.
2. Hermes Bot Mode에서 관리하는 봇으로 등록하고 각자의 고정 `Bot Chat`을 확인한다. 프로필 생성만으로 봇 메시징 기능이 완성됐다고 간주하지 않는다.
3. 모니카의 고정 대화에서 `message_agent` 사용 가능 여부와 두 전문 봇의 명단·역할을 확인한다.
4. listener의 `hermes.profile=monica`, `session_title=Bot Chat`으로 기본 대상을 설정한다. 이 값은 실제 프로필과 고정 대화가 준비된 뒤 적용한다.
5. 모니카가 요청을 분배하고 각 봇의 완료/실패 결과를 받아 종합하는 흐름을 검증한다. 단순 접수와 작업 완료를 구분한다.

**대화 구분:** 봇의 고정 Bot Chat은 분배 창구로 계속 유지한다. listener의 “새 대화”는 같은 프로필에서 별도 일반 작업 세션을 만드는 기능이다. 일반 세션에서 봇 간 메시징 도구가 항상 있다고 가정하지 않는다. 전문 봇 요청은 모니카의 고정 대화로 돌아가 처리하거나, 후속 단계의 작업 라우터가 `task_id`와 결과 대상 세션을 지정해 그 창구를 경유하게 한다. 고정 대화를 초기화해 새 작업을 만드는 방식은 사용하지 않는다.

**완료 조건:** 모니카에게 한 번 요청하면 전문 봇 한 개 또는 두 개가 실제로 처리하고, 오류도 포함한 결과가 모니카에 도착한다. 작업 중 다른 음성 요청이 대기열에 보존된다.

## 5. 단계 B — 시세·뉴스 도구와 분석 스킬

### 먼저 결정할 입력

- 국내/미국 중 먼저 지원할 시장, 관심 종목과 종목명 별칭
- 사용할 시세/뉴스 제공자, 실시간·지연 시세 조건, 인증 방식과 호출 한도
- 조회 빈도, 보고 시간, 결과를 받을 채널

### 공통 도구 인터페이스 초안

| 도구 | 입력 | 핵심 출력 |
|---|---|---|
| `get_quote` | 종목 코드, 거래소 | 가격, 통화, 전일 대비, 거래량, 시장 상태 |
| `get_history` | 종목, 기간, 간격 | 기준 시각이 있는 시계열, 수정주가 여부 |
| `search_market_news` | 종목/키워드, 기간 | 제목, 출처 URL, 발행/수집 시각 |
| `get_keyword_trends` | 주제, 관찰 기간, 비교 기간 | 빈도 변화, 집계 방식, 근거 기사 |

모든 응답에 `source`, `as_of`, `fetched_at`, `is_delayed`, `cache_age_seconds`, `status`를 포함한다. 종목·거래소·통화도 명시한다. 데이터가 오래됐거나 조회가 실패하면 그 상태를 반환하며 이전 가격을 현재가처럼 표시하지 않는다. 인증은 도구 서버의 환경/자격 저장소에서 관리하고 SKILL.md에는 값을 넣지 않는다.

주식 스킬은 종목 확인 → 기준 시각/시장 상태 확인 → 시세와 뉴스 조회 → 비교 → 출처와 함께 설명하는 순서를 정의한다. 키워드 스킬은 집계 범위·비교 기준·중복 기사 처리·발생 시점을 함께 다룬다. 첫 버전의 도구는 데이터 조회와 분석을 제공한다.

**완료 조건:** 같은 종목명이 거래소별로 모호하면 확인을 요청한다. 휴장·지연 시세·API 실패·캐시 사용이 결과에 표시된다. 실제 제공자 응답과 봇의 숫자·출처가 일치한다.

## 6. 단계 C — n8n 자동 수집과 호출 연결

배포 위치는 현재 PC·상시 켜진 NAS/서버·클라우드 중에서 정한다. 상시 알림이 필요하면 그 시간 동안 실행 가능한 환경을 선택한다. 설치 위치와 API 인증 정보는 이 단계 시작 시 정하고, 지금 계획 작성만으로 설치하거나 연결하지 않는다.

### 첫 워크플로우: 관심 종목 정기 보고

```text
Schedule Trigger
 → 관심 종목 읽기
 → 시세/뉴스 API 호출
 → 시각·응답 검사 / 캐시·DB 저장
 → 분석 요청 생성(task_id)
 → 모니카 고정 대화로 전달
 → 주식 봇 분석
 → 완료 이벤트 수신 / 결과 저장 / 알림
```

### 두 번째 워크플로우: 중요 변화 알림

```text
일정 또는 수집 이벤트
 → 거래량·가격·키워드 변화 계산
 → 사용자 설정 조건 검사
 → 중복 이벤트 키와 알림 대기 시간 검사
 → 조건 충족 시에만 봇 분석 요청
 → 결과와 데이터 기준 시각을 함께 알림
```

조건 계산과 중복 방지는 코드/워크플로우에서 결정적으로 처리한다. 모든 가격 변동마다 LLM을 호출하지 않고 중요 이벤트에 분석을 요청한다. 알림 대상과 실제 전송은 사용자가 설정한 채널로 한정한다.

### 봇이 n8n을 필요할 때 호출하기

- 처음에는 인증된 Webhook과 고정된 입력 JSON을 사용하거나 MCP 서버로 필요한 도구만 노출한다.
- MCP Server Trigger에 Workflow Tool을 연결해 `관심 종목 보고 생성`, `저장된 보고 조회` 등 명확한 작업으로 제공한다.
- 입력값(종목·기간·관심 목록 ID)과 출력값(task_id·접수 상태·결과 위치)을 검증한다. 접수 응답과 최종 결과를 구분한다.
- 시세 API 호출·파싱·저장 로직은 여러 봇/워크플로우가 공유한다. 같은 데이터를 각 봇이 별도로 수집해 서로 다른 숫자를 만드는 구조를 피한다.

**완료 조건:** 예약 실행이 재시작 이후에도 동작하고, 한 이벤트가 중복 실행되더라도 같은 보고/알림이 한 번만 전달된다. 봇 실행 실패와 API 실패가 각각 추적된다.

## 7. 단계 D — 작업 상태와 복구

- listener 입력 ID → 모니카 요청 ID → 전문 봇 delivery ID → n8n execution ID를 `task_id`로 연결한다.
- 상태는 `accepted / collecting / analyzing / completed / failed / unknown`으로 구분한다.
- 데이터 조회는 호출 한도 안에서 재시도하되, 봇 요청·알림은 같은 이벤트 키를 사용해 중복을 막는다.
- 전송 결과가 불명확한 요청은 자동으로 새 요청으로 만들지 않는다. 저장된 접수 기록이나 완료 기록을 먼저 조회한다.
- 사용자에게 현재 선택된 대화, 대기 건수, 완료/실패 상태를 표시한다. TTS를 추가하면 재생 음성의 재호출을 차단한다.

## 8. 권장 구현 순서와 검증

| 순서 | 결과물 | 검증 |
|---|---|---|
| 0 (현재) | listener 세션 연결/후속 입력 | 같은 세션 유지, 작업 중 큐, 새 대화/이전/재개, 접수 불명확 시 중복 방지 |
| 1 | 모니카 + 전문 봇 두 개 | 실제 Bot Chat 메시징과 비동기 결과 회신 |
| 2 | 시장 한 곳의 조회 도구 + 스킬 | 시각·통화·종목·출처·지연 상태의 정확한 전달 |
| 3 | n8n 정기 보고 한 개 | 예약·재시도·중복 방지·완료 알림 |
| 4 | 조건 알림과 상태 화면 | 여러 작업/세션이 동시에 실행되어도 결과 대상 유지 |

새 봇과 n8n을 한 번에 도입하기보다 각 단계의 실제 요청 한 개가 처음부터 끝까지 성공하는 것을 확인한다. 현재 변경에서 봇과 n8n을 생성하거나 인증 정보를 저장하지 않았다.
